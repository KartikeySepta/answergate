Ask a question across many videos. Get the seconds that answer it.

Not a summary. Ranked, timestamped clips with verbatim quotes — and nothing at all when nothing in your videos answers you. Runs entirely on your own machine if you want it to.

What it actually does

$ answergate clips fitness "does creatine cause bloating?"

2 clip(s) answer: "does creatine cause bloating?"

[1] @JeffNippard — Creatine: Everything You Need To Know
    ~19:30 → ~20:18   https://youtu.be/xY7abc?t=1167
    "water retention is intramuscular, not subcutaneous"
    ! CONFLICTS with [2]

[2] @LaylaNorton — The Truth About Creatine
    8:02 → 9:14   https://youtu.be/qM3def?t=479
    "most people do notice some puffiness in the first two weeks"
    ! CONFLICTS with [1]

9 video(s) had no answering clip — 3h 51m you can skip

Ordinary retrieval returns chunks that are topically similar. That is why a summariser can never tell you a video is padding — it has no concept of a chunk failing to answer. An answer gate labels every retrieved chunk answers / mentions / unrelated, and that last line only exists because of it.

Two guarantees, enforced in code rather than asked for in a prompt

  • A quote is really in the transcript. The model returns a sentence number; the text is sliced from the chunk by the program. The model never supplies displayed text, so it cannot invent or corrupt it.
  • A rate limit never looks like an empty result. "We checked and found nothing" and "we could not check" are different facts, reported differently. Conflating them is how a tool teaches people not to trust it.

Install

pip install "answergate[full]"

The bare pip install answergate skips the ML stack, so it will not pull ~2GB of torch on someone who only wants to read the CLI help. [full] gets the working thing.

Three system dependencies

These are for pulling audio out of YouTube. They are the honest cost of reading videos that have no captions.

NeededWhyInstall
FFmpegyt-dlp's audio postprocessorbrew install ffmpeg
DenoLets yt-dlp pass YouTube's JS challenge instead of silently returning an empty format listbrew install deno
PO token providerFresh per-video token. Without it, downloads intermittently 403 even when listing worksdocker compose up -d pot-provider
The PO token provider must be running every time you scrape. It is a background service, not one-time setup. A 403 Forbidden on download when format listing worked fine means it is not up — check docker ps.

Using it

# add one video — scrape, transcribe, chunk, index, extract claims
answergate add "https://www.youtube.com/watch?v=VIDEO_ID" my_research

# or many at once
answergate batch urls.txt my_research

# ask
answergate clips my_research "your question"
answergate clips my_research "your question" --json

# how much of each video contains checkable claims
answergate density my_research

Your agent gets search_clips and list_workspaces. The tool description tells the agent it can come back empty — so an agent that gets "no source answers this" reports that, instead of confabulating from the nearest passage. Dependency-free: MCP is JSON-RPC over stdio, so there is no SDK to install.

Running fully local

ollama serve && ollama pull llama3.2
LLM_BACKEND=ollama answergate clips my_research "your question"

No transcript and no query leaves your machine, and there is no per-day quota. You can also split routing — bulk claim extraction local, only the gate on a cloud model: 

EXTRACTION_BACKEND=ollama GATE_BACKEND=gemini answergate clips my_research "..."

Does it actually work?

Retrieval is always local, so provider choice cannot affect it. The gate is an LLM call, so it can. Measured against 24 hand-labelled examples in rag/evals/dataset_answergate_v1.json:

ProviderAnswers foundFabricated clipsUnusable replies
Gemini 3.1 Flash Lite7 of 700 of 6
qwen2.5:7b — local3 of 700 of 6
llama3.2 3B — local4 of 731 of 6

Local models don't lie to you. They just find less. qwen2.5:7b fabricated nothing across the whole set — it declined to return a verdict for half the chunks, and a chunk with no verdict is never shown. llama3.2 at 3B is the one to avoid: it asserted three answers that were not there. Raw label accuracy (92% / 38% / 54%) is the wrong metric and isn't the headline — it scores a missing verdict as wrong, but in use that just means the clip isn't displayed. Constrained JSON decoding removed parse failures entirely: 1 of 6 unusable before, 0 of 6 after.

What the verbatim guard does not cover. It stops invented text. It cannot stop wrong judgment — all three llama3.2 fabrications quoted real sentences and simply judged them wrong.

Reproduce any of this yourself:

LLM_BACKEND=gemini python3 evals/evaluate_gate.py map
LLM_BACKEND=ollama python3 evals/evaluate_gate.py map

What this does not do

  • It does not judge whether an argument is any good. Like scite.ai for papers, it can show you that sources conflict; it cannot tell you who is right.
  • It cannot reach beyond the videos you added. Its authority is capped by theirs.
  • It is not a better summariser than NotebookLM.
  • It is not the fastest way to skip filler in one popular video — SponsorBlock is crowdsourced, instant and free. This earns its keep on the long tail: videos with no crowd data and no captions, and questions that are yours rather than the crowd's.
  • Claim density ships as a rough diagnostic, not a ranking. Measured across 7 real videos it sat at 87–100% for everything, because chunks are ~180 words and nearly every chunk yields a claim — it tracks chunk size, not substance.

How it works

YouTube URL
  → yt-dlp + Whisper/Gemini        audio, not captions
  → chunk (~180 words, overlapping)
  → embed + index                  local embeddings, Qdrant on disk
  → extract claims                 evidence chunk_ids validated

question
  → hybrid retrieve (vector + BM25) + cross-encoder rerank
  → ANSWER GATE                    1 batched call: answers/mentions/unrelated
  → conflict check                 1 batched call over the kept clips
  → skip report                    pure arithmetic
  → ranked clips + timestamps

~2 LLM calls per question. Cheap per use is a design goal, not an optimisation: a tool you hesitate to run is a tool you stop running.
